# 《原生开发六大痛点清单》

> 标题沿用课程名称，实际整理 10 条。代码位置分两层标注：
> - **重构前**：`stage1-class01` 标签中的代码，用来保留“原始技术形态”的真实摩擦；
> - **重构后**：当前 `stage1-class02` 代码，用来标明改进落点。

## 一、重复

### 1. 驱动加载和连接获取在 Servlet 中重复出现

- **重构前位置**：`com.taskmaster.servlet.TaskListServlet#doGet`，`stage1-class01` 对应 `src/main/java/com/taskmaster/servlet/TaskListServlet.java:41-42`。
- **归类**：重复。
- **现象**：`Class.forName(...)` 与 `DriverManager.getConnection(...)` 直接写在查询逻辑里。只要再写新增、修改、删除，就要复制同一套连接代码；异常关闭也容易漏。
- **改进设想**：抽出 `DBUtil`，集中负责驱动、连接参数和连接创建。
- **重构落点**：`src/main/java/com/taskmaster/util/DBUtil.java`；各 DAO 通过 `DBUtil.getConnection()` 获取连接。

### 2. ResultSet 到实体的字段映射重复

- **重构前位置**：`TaskListServlet#doGet`，`stage1-class01` 对应 `TaskListServlet.java:48-62`。
- **归类**：重复。
- **现象**：`rs.getLong("id")`、`rs.getString("title")` 等映射和类型转换与 SQL 列名完全绑在 Servlet 中。新增一个查询就要再抄一遍，列名改动时容易漏改。
- **改进设想**：DAO 内部使用统一的 `map(ResultSet)` 方法，Servlet 只接收 `Task` 对象。
- **重构落点**：`src/main/java/com/taskmaster/dao/impl/TaskDaoImpl.java:160-175`。

### 3. 状态、优先级的数字含义在多层重复

- **代码位置**：`src/main/java/com/taskmaster/entity/Task.java` 的 `getStatusText()`、`getPriorityText()`；`TaskDaoImpl` 的排序 SQL；JSP 中的 `task.getStatus() == 2` 判断。
- **归类**：重复（同时带有耦合）。
- **现象**：`0/1/2` 和 `1/2/3` 的含义同时出现在实体、SQL、Servlet 和 JSP 中。新增状态或调整顺序时，需要全工程搜索数字。
- **改进设想**：用枚举或集中常量表达状态/优先级，数据库值通过 `valueOf` 转换；排序规则也由同一套常量生成。
- **当前状态**：展示文案已经收口到 `Task` 的只读属性，但数字常量仍未完全枚举化，属于下一轮可改进项。

## 二、耦合

### 4. SQL 与 Web 控制器耦合

- **重构前位置**：`TaskListServlet#doGet`，`stage1-class01` 对应 `TaskListServlet.java:44-47`。
- **归类**：耦合。
- **现象**：Servlet 同时负责接收请求、拼 SQL、执行查询、映射实体和选择视图。任何 SQL 调整都必须修改控制器，Web 层和数据库层无法独立变化。
- **改进设想**：DAO 接口只暴露业务语义方法，SQL 和 JDBC 细节留在实现类。
- **重构落点**：`src/main/java/com/taskmaster/dao/TaskDao.java` 与 `TaskDaoImpl.java`；`TaskListServlet` 只调用 `taskDao.list(...)`。

### 5. JSP 脚本片段承担了过多数据逻辑

- **重构前位置**：`stage1-class01` 的 `src/main/webapp/WEB-INF/views/list.jsp:4-10`、`:44-69`。
- **归类**：耦合。
- **现象**：JSP 直接做类型转换、空值判断、状态判断和循环输出，页面结构与 Java 逻辑混在一起，修改样式时容易碰到业务判断。
- **改进设想**：Servlet 准备展示数据，JavaBean 提供只读展示属性，JSP 只负责输出；输入输出统一做 HTML 转义。
- **重构落点**：当前 `list.jsp` 使用 `currentUser`、`tasks`、统计属性和 `Task#getStatusText()`；所有用户数据通过 `WebUtil.escapeHtml(...)` 输出。
- **仍未完全消除**：当前项目仍是原生 JSP 脚本片段，后续可引入 JSTL/EL 或自定义标签进一步收敛。

### 6. 用户身份被硬编码在查询和页面中

- **重构前位置**：`stage1-class01` 的 `TaskListServlet.java:46` 使用 `WHERE user_id = 1`；`:69-70` 固定写入“任务管理员”。
- **归类**：耦合。
- **现象**：没有登录也能看到固定用户的任务，用户身份不可替换，也无法做数据隔离。
- **改进设想**：登录成功后把用户放入 Session；查询从 Session 取 `userId`；所有 DAO 更新/删除都带 `user_id` 条件。
- **重构落点**：`LoginServlet`、`AuthFilter`、`BaseServlet`；`TaskDaoImpl` 的查询、更新、删除全部接收 `userId` 并加入 SQL 条件。

### 7. 写操作和视图转发混在一起，缺少 PRG 边界

- **重构前/开发中位置**：阶段一只有列表查询；实现新增时，如果沿用“POST 后直接 forward 到列表”的写法，浏览器刷新会再次提交表单。
- **归类**：耦合（请求处理与页面渲染耦合）。
- **现象**：POST 请求承担写库和展示两种职责，刷新时浏览器会重复发送最后一次 POST。
- **改进设想**：POST 只负责写库，成功后 `sendRedirect` 到 GET 列表；一次性提示放 Session 并在下一次 GET 消费。
- **重构落点**：`TaskAddServlet`、`TaskUpdateServlet`、`TaskDeleteServlet`、`TaskStatusServlet` 均使用 `redirect(...)`；`WebUtil.flash(...)` 与 `moveFlashToRequest(...)` 实现一次性提示。

## 三、配置

### 8. 数据库连接参数散落在 Java 源码中

- **重构前位置**：`stage1-class01` 的 `TaskListServlet.java:31-37`。
- **归类**：配置。
- **现象**：URL、用户名和密码来源写在 Servlet 内，换数据库或换环境需要改源码并重新打包；凭据也容易进入版本库。
- **改进设想**：配置外置为 `db.properties` 或环境变量，代码只读取配置键；密码不提交到 Git。
- **重构落点**：`DBUtil.java` 支持 `TASKMASTER_DB_*` 环境变量和 `classpath:db.properties`；仓库只保留 `db.properties.example`。

### 9. 页面编码依赖每个 JSP 单独声明

- **重构前位置**：`stage1-class01` 的 `list.jsp:1` 单独声明 `pageEncoding="UTF-8"`；阶段一没有统一请求编码过滤器。
- **归类**：配置。
- **现象**：新增 JSP 或新增 POST 参数时，必须手动重复设置编码；只要漏掉一处，就可能出现中文乱码。
- **改进设想**：使用 `EncodingFilter` 在任何参数解析之前统一设置请求/响应编码。
- **重构落点**：`src/main/java/com/taskmaster/filter/EncodingFilter.java`，在 `web.xml` 中映射 `/*`。

### 10. Servlet、Filter、错误页映射手工堆积

- **重构前位置**：`stage1-class01` 的 `web.xml:9-16` 只有列表 Servlet 映射。
- **归类**：配置。
- **现象**：每新增一个用例都要同时改 Java 类、`web.xml` 映射、JSP 路径和错误页；映射遗漏时会出现 404 或 500，且问题不一定在 Java 代码里。
- **改进设想**：小项目可以用 `@WebServlet` / `@WebFilter` 降低重复配置；需要统一权限时保留显式 Filter 配置；同时为 400/403/404/500 配置统一错误页。
- **重构落点**：当前 `web.xml` 保留显式映射，便于观察配置成本，并增加 `EncodingFilter`、`AuthFilter`、Session 配置和统一错误页。

### 11. 每个请求新建物理数据库连接（补充项）

- **代码位置**：`src/main/java/com/taskmaster/util/DBUtil.java#getConnection`；每个 DAO 方法调用一次。
- **归类**：配置（运行环境/资源管理）。
- **现象**：每次查询或写入都新建 `Connection`，并发上升时连接建立成本高，数据库连接数也难统一控制。
- **改进设想**：引入 DBCP2、HikariCP 或容器 JNDI `DataSource`，DAO 只依赖 `DataSource`，不改变 SQL 和实体映射。
- **当前状态**：本阶段刻意保留原生 JDBC 形态，连接池列为后续演进项。
