# TaskMaster SSM 三层架构调用图与职责说明

## 1. 架构调用图

```mermaid
flowchart LR
    B[Browser] -->|HTTP| DS[DispatcherServlet]
    DS -->|HandlerMapping| C[Controller<br/>AuthController / TaskController]
    C -->|调用接口| S[Service<br/>TaskService / UserService]
    S -->|调用接口| M[Mapper Proxy<br/>TaskMapper / UserMapper]
    M -->|namespace + SQL id| X[Mapper XML]
    X -->|JDBC| DB[(MySQL taskmaster)]
    C -->|返回 view name| VR[InternalResourceViewResolver]
    VR -->|forward| JSP[JSP views]
```

## 2. 每层职责

| 层 | 主要类 | 职责 | 不应承担 |
|---|---|---|---|
| Web / Controller | `AuthController`、`TaskController`、`GlobalControllerAdvice` | 接收参数、登录态判断、调用 Service、选择视图、PRG 重定向 | SQL、JDBC、直接 new Mapper |
| Service | `TaskServiceImpl`、`UserServiceImpl` | 业务用例、语义校验、事务边界、组织持久化调用 | JSP 渲染、直接操作 ResultSet |
| Persistence | `TaskMapper`、`UserMapper`、`*Mapper.xml` | 参数绑定、SQL、结果映射 | 页面跳转、Session 判断 |
| Entity | `Task`、`User` | 承载业务字段与只读展示属性 | 依赖 Servlet/JDBC/SpringMVC |
| Infrastructure | `PooledDataSource`、`SqlSessionFactory`、`DataSourceTransactionManager` | 连接池、MyBatis 会话、事务资源 | 具体任务业务规则 |

## 3. 一次请求的调用链

### `GET /tasks`

1. `DispatcherServlet` 接收请求并找到 `TaskController#list`。
2. `AuthInterceptor` 检查 Session 登录用户。
3. Controller 解析筛选参数，调用 `TaskService.list(...)`。
4. `TaskServiceImpl` 使用构造器注入的 `TaskMapper` 代理执行查询。
5. MyBatis 根据 namespace 和 method 找到 `TaskMapper.xml`，完成参数绑定和结果映射。
6. Controller 把任务和统计放入 Model，返回 `list`，视图解析器转发 JSP。

### `POST /tasks/add`

1. `CsrfInterceptor` 校验 `_csrf`。
2. Controller 绑定表单并调用 `TaskService.create`。
3. `@Transactional` 让插入由事务管理器统一管理。
4. Controller 写入重定向提示，返回 `redirect:/tasks`。
5. 浏览器重新 GET 列表，刷新不会重复提交。

## 4. 三套配置的分工

| 配置 | 负责内容 | 不负责内容 |
|---|---|---|
| `applicationContext.xml` | DataSource、SqlSessionFactory、Mapper 扫描、Service 装配、事务管理器 | Controller 扫描、视图解析、拦截器 |
| `spring-mvc.xml` | Controller/Advice 扫描、注解驱动、视图解析器、拦截器、静态资源 | Mapper Bean、数据库连接、事务 |
| `mybatis-config.xml` | MyBatis 设置、类型别名、全局映射行为 | Spring Bean、数据源、MVC 视图 |

`web.xml` 只负责启动根容器 `ContextLoaderListener` 和中央控制器 `DispatcherServlet`。

## 5. 技术由痛点逼出来

| 原生痛点 | 引入技术 | 解决方式 |
|---|---|---|
| 每处 `new` 下层实现 | Spring Core DI | 构造器注入与 Setter 注入由容器完成 |
| Servlet 自己分派 `opt` | SpringMVC | `@Controller` + `@RequestMapping` 交给 DispatcherServlet |
| Connection/Statement/ResultSet 六步法重复 | MyBatis | Mapper 接口 + XML，代理完成参数和结果映射 |
| SQL 混在 Java 业务代码 | Mapper XML | SQL 集中到 `mappers/*.xml` |
| 多写操作缺少事务边界 | Spring Transaction | Service 写方法加 `@Transactional` |
