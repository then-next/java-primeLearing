## 一、实验目的

1. 理解 HTTP 请求/响应模型、Tomcat 部署方式和 Servlet 生命周期。
2. 跑通“浏览器 → Servlet → MySQL → JSP”的完整数据通路。
3. 使用 JavaBean 承载任务数据，完成 `ResultSet` 到实体对象的映射。
4. 抽取 `DBUtil`，设计 DAO 接口与实现，降低 Web 层和持久化层的耦合。
5. 使用 `EncodingFilter` 统一解决中文乱码。
6. 实现登录、任务增删改查，并用 PRG（POST-Redirect-GET）避免刷新重复提交。
7. 对原生技术栈的重复、耦合、配置问题进行归类复盘。

## 四、关键代码

### 4.1 DBUtil：连接参数与驱动收口

`DBUtil` 的优先级是“环境变量 → `db.properties` → 默认 URL/用户名”，密码没有默认值，未配置时直接给出可读异常，避免把真实密码写进源码。

```java
public static Connection getConnection() throws SQLException {
    String url = read("TASKMASTER_DB_URL", "jdbc.url", DEFAULT_URL);
    String user = read("TASKMASTER_DB_USER", "jdbc.username", "taskmaster_app");
    String password = read("TASKMASTER_DB_PASSWORD", "jdbc.password", "");
    if (password.isEmpty()) {
        throw new SQLException("数据库密码未配置：请设置 TASKMASTER_DB_PASSWORD 或 db.properties");
    }
    return DriverManager.getConnection(url, user, password);
}
```

### 4.2 DAO：SQL、参数绑定和结果集映射

`TaskDaoImpl` 中的查询通过 `PreparedStatement` 绑定 `userId`、关键词和状态，列表排序固定为“进行中 → 待办 → 已完成”，同状态按优先级和截止日期排序。

```java
StringBuilder sql = new StringBuilder(
        "SELECT " + COLUMNS + " FROM t_task WHERE user_id = ?");
List<Object> parameters = new ArrayList<>();
parameters.add(userId);
if (keyword != null && !keyword.isEmpty()) {
    sql.append(" AND (title LIKE ? OR description LIKE ?)");
}
if (status != null) {
    sql.append(" AND status = ?");
}
```

结果集映射统一放在 `map(ResultSet)` 中，Servlet 不再直接读取 JDBC 列。

### 4.3 EncodingFilter：在任何参数读取前设置 UTF-8

```java
request.setCharacterEncoding("UTF-8");
response.setCharacterEncoding("UTF-8");
chain.doFilter(request, response);
```

过滤器顺序在 `web.xml` 中先于 `AuthFilter`，保证登录表单和任务表单里的中文参数按 UTF-8 解析。

### 4.4 登录与 Session

`LoginServlet` 先校验 CSRF，再查询 `UserDao`，用 `PasswordUtil.verify` 校验摘要。登录成功后：

```java
HttpSession session = request.getSession();
request.changeSessionId();
user.setPasswordHash(null);
user.setSalt(null);
session.setAttribute(WebUtil.SESSION_USER, user);
WebUtil.rotateCsrfToken(session);
response.sendRedirect(request.getContextPath() + "/tasks");
```

清空密码字段后再放 Session，避免页面或日志意外拿到摘要；`changeSessionId()` 降低会话固定风险。

### 4.5 新增任务与 PRG

`TaskAddServlet#doPost` 完成表单校验、插入数据库后不转发 JSP，而是：

```java
taskDao.insert(task);
WebUtil.flash(request, "success", "任务“" + task.getTitle() + "”已创建");
response.sendRedirect(request.getContextPath() + "/tasks");
```

下一次 GET 才消费 Session 中的一次性提示。刷新列表只是重复 GET，不会再次执行 INSERT。

## 七、原理理解

1. **Servlet 生命周期**：Tomcat 创建 Servlet 实例后调用 `init()`，请求到达时调用 `service()`/`doGet()`/`doPost()`，应用关闭时调用 `destroy()`。本项目把 DAO 字段作为 Servlet 的无状态依赖，业务状态放在请求或 Session 中。
2. **HTTP 请求响应**：GET 用于读取和筛选，POST 用于写操作；写操作成功后返回 302 和 `Location`，浏览器再发起 GET，形成 PRG。
3. **Session**：登录用户和 CSRF 令牌放在 Session；Session Cookie 设置 `HttpOnly`，页面响应设置 `Cache-Control: no-store`，降低退出后回退看到旧页面的风险。
4. **JDBC**：`PreparedStatement` 负责参数绑定，避免 SQL 注入；`try-with-resources` 按 ResultSet → Statement → Connection 的顺序关闭资源。
5. **Filter**：`EncodingFilter` 解决参数解码，`AuthFilter` 解决统一登录拦截；两者都在 Servlet 之前执行，避免每个 Servlet 重复写相同逻辑。

## 八、遗留与改进

1. 安装并实际验证 Tomcat 9.0.x + JDK 11；当前环境验证使用 Tomcat 11 迁移包，不能替代课程要求的 Tomcat 9 实机验证。
2. 把 `DBUtil` 的直连方式升级为连接池（DBCP2/HikariCP 或 JNDI），减少每次请求建立物理连接的开销。
3. 用 JSTL/EL 或自定义标签继续收敛 JSP 脚本片段。
4. 把加盐 SHA-256 替换为 BCrypt/Argon2，并增加登录限流和审计。
5. 增加 DAO 层自动化测试与浏览器端回归测试；当前验证以 PowerShell HTTP 请求和人工页面检查为主。
6. 任务状态和优先级用枚举/常量替换散落的数字。

## 九、结论

本项目在不引入 Spring、MyBatis 和前端框架的前提下，完成了登录、任务列表、新增、编辑、删除、状态变更、搜索筛选、中文编码、CSRF 防护和 PRG 跳转。通过 `DBUtil`、DAO 接口/实现、`EncodingFilter`、`AuthFilter` 和统一的 `WebUtil`，把阶段一暴露出的重复连接、SQL 耦合、页面逻辑耦合和配置分散问题做了可验证的收敛。

当前最明确的环境缺口是 Tomcat 9/JDK 11 未安装，报告中已如实记录，没有把 Tomcat 11 迁移验证冒充成 Tomcat 9 验证。
