# 《持久层重构收益对比表》

## 1. 统计口径

- **改造前**：`legacy/native-jdbc` 中的 JDBC 接口、实现和 `DBUtil`；
- **改造后**：`mapper` 包中的 Mapper 接口与 `mappers/*.xml`；
- 行数包含空行与注释，便于用同一口径复核；
- SQL 位置按真正的 SQL 语句声明统计，不把方法名 `insert/update/delete` 当作 SQL。

## 2. 代码行数对比

| 改造前文件 | 行数 | 改造后文件 | 行数 |
|---|---:|---|---:|
| `TaskDao.java` | 18 | `TaskMapper.java` | 23 |
| `UserDao.java` | 7 | `UserMapper.java` | 6 |
| `TaskDaoImpl.java` | 176 | `TaskMapper.xml` | 75 |
| `UserDaoImpl.java` | 35 | `UserMapper.xml` | 19 |
| `DBUtil.java` | 59 | — | 0 |
| **合计** | **295** | **合计** | **123** |

**结果：持久层相关文件从 295 行降到 123 行，减少 172 行，约减少 58.3%。**

| 指标 | 改造前 | 改造后 |
|---|---:|---:|
| Java 持久层行数 | 295 | 29（两个 Mapper 接口） |
| Java 中的 SQL 语句位置 | 9 | 0 |
| SQL XML 行数 | 0 | 94 |

## 3. SQL 散落位置对比

| 指标 | 改造前 | 改造后 | 说明 |
|---|---:|---:|---|
| SQL 语句总数 | 9 | 9 | 功能没有减少 |
| 包含 SQL 的物理文件 | 2 个 Java 实现类 | 2 个 Mapper XML | SQL 从编译代码移到声明式 XML |
| Java 业务代码中的 SQL 位置 | 9 | 0 | Service/Controller 不再维护 SQL 字符串 |
| 每个方法的 JDBC 六步法 | 每个 DAO 方法重复 | Mapper 代理统一处理 | 连接、Statement、参数、映射由框架承担 |
| 用户条件 | 分散于多个 DAO 方法 | 集中在 Mapper XML | 便于审查越权条件 |

改造前：

- `TaskDaoImpl`：8 个 SQL 位置；
- `UserDaoImpl`：1 个 SQL 位置。

改造后：

- `TaskMapper.xml`：8 个 statement；
- `UserMapper.xml`：1 个 statement。

> 真正收益不是 SQL 变少，而是 SQL 位置从 Java 实现类转移到 Mapper XML，Java 不再承担连接管理和 SQL 字符串维护。

## 4. 质量收益

| 维度 | 原生 JDBC | MyBatis / SSM |
|---|---|---|
| 资源关闭 | 每个方法手写 `try-with-resources` | MyBatis 会话统一管理 |
| ResultSet 映射 | 手写 `resultSet.getXxx` | `resultMap` 声明式映射 |
| 参数绑定 | 手工按序号 `setXxx` | `#{property}` 按名称绑定 |
| 接口实现 | 每个 DAO 写实现类 | Mapper 接口由 JDK 动态代理实现 |
| 事务 | Service 手工控制 | `@Transactional` + 事务管理器 |
| SQL 审查 | 在 Java 字符串中搜索 | 直接审查 Mapper XML |

## 5. 代价与遗留

1. 多了 XML 映射文件，需要保证接口方法名与 statement id 一致；
2. namespace 必须与 Mapper 接口全限定名一致；
3. `jdbc.properties` 需要按环境填写，真实密码不能提交；
4. 调试时要同时看接口、XML 和 SQL 日志。

## 6. 结论

持久层 Java 代码从 **295 行降到 29 行接口**，9 处 SQL 从 Java 类迁移到 2 个 Mapper XML；SQL 总量不变，但 SQL 与 Java 业务职责被明确分离。收益主要来自重复六步法消失、接口无实现类可运行、SQL 可集中审查、事务边界可声明。
